# 워크플로우 전후 독립 실측

## 판정과 범위

**로컬 워크플로우 회귀검증 점수: 변경 전 35/100 → 변경 후 100/100, +65점입니다.** 동일한 20개 실행 가능한 목표 계약 검사를 각각 5점으로 고정했습니다. 통과 수는 7/20 → 20/20, +13개(+185.71%), 통과율은 35% → 100%(+65%p)입니다. 구버전 점수 게이트를 실제 실행한 종료코드는 1, 신버전은 0입니다. 전체 사이트 점수, 운영 품질, 모델 판단 정확도, 비용 절감 점수가 아닙니다.

`_workspace/workflow-renewal-benchmark/RUBRIC.json`을 첫 실행 전에 작성했습니다. 결과 확인 후 항목·가중치를 바꾸지 않았습니다. 초기 정적 HTML fixture가 기존 동적 렌더 판정을 유발한 실행 오류는 `attempt1-error.log`에 보존했습니다. 정적 기사 본문을 충분히 넣고 렌더 실행을 명시적으로 금지한 후 재실행했습니다. 이 교정은 같은 입력을 양쪽에 적용하며 채점 기준은 유지했습니다.

기준은 보존/배정 25점, HTML·원본·캐시 30점, usage·예산 20점, 검사 최신성 15점, Grok 호환성 10점입니다. 기능이 없는 구버전은 목표 계약 미충족으로 실패 처리했습니다. 예를 들어 `workflow_contract.py`가 없는 구버전의 호출 실패만으로 ‘오래된 검사 거절’에 성공했다고 인정하지 않았습니다. 정상 검사가 먼저 성공한 뒤 오래된 검사·실패 검사만 거절해야 통과입니다. 마찬가지로 구버전의 미지원 `--usage-json` 오류는 유효한 usage 입력을 먼저 수용하지 못하므로 잘못된 값 검증 성공으로 인정하지 않았습니다.

**편향:** 새 기능을 포함한 목표 계약 평가라 신규 구현에 유리합니다. 독립적 무작위 운영 표본이나 외부 정답집 평가는 아닙니다. 구버전에서 통과한 공통 7개 항목은 신버전도 모두 통과했습니다(공통 호환성 7/7 → 7/7). 향후 더 나은 기준은 실제 실행자 연결·운영 실패 복구·비공개 평가 표본을 포함한 별도 버전입니다. 이번 결과를 보고 가중치를 다시 정하지 않았습니다.

## 실제 실행한 입력

- 합성 후보: OpenAI 도메인 205개와 미배정 도메인 1개, 총 206개입니다. registry는 빈 목록이며 기본 lane 세 개를 사용합니다. 따라서 복잡한 registry 중첩 배정이나 동일 기사 중복 입력까지 대표하지 않습니다.
- 저장 운영 입력: `_workspace/radar-20260718/01c_community_seeds.json`, 91개 seed입니다. 입력 원본 해시를 기록했으며 내용·제목·개인정보는 보고서나 raw 결과에 출력하지 않습니다. 기존 입력을 그대로 양쪽에 공급했습니다. 생성된 운영 job/audit 원문은 해당 benchmark 작업 폴더 안에서만 만들었다가 제거했습니다.
- HTML: 본문 사실 3개, head/script/style 노이즈 세 종류, 앞부분 12,000자 이후 등장하는 별도 본문 사실 1개입니다. JSON passthrough와 두 번째 cache hit도 실제 호출했습니다. HTTP는 로컬 mock 응답이며 네트워크·브라우저·모델 호출이 아닙니다.
- usage: unknown, 입력 0/출력 8의 partial, 음수·boolean·소수·문자열 거절, 중복 finish 거절입니다.
- 검사 최신성: 정상 명령 exit 0, 입력 파일 변경, 실패 명령 exit 3을 실제 로컬 subprocess로 실행했습니다.
- Grok: 구·신 소스에서 동일 순수 함수 본문만 capability-free Node VM으로 실행했습니다. CLI main이나 fetch는 실행하지 않았습니다. 기본 프롬프트와 4개 인용 추출을 비교했습니다.

## 전달용 산출물 크기

단위는 Unicode 글자 수와 UTF-8 바이트입니다. tokenizer를 사용하지 않았으므로 **토큰 수가 아닙니다.** 실제 외부 실행자 전송을 관측한 값이 아니라 실행 코드가 생성한 전달용 파일/프롬프트의 크기입니다. job은 생성된 전체 job JSON의 합계이고 감사 정본은 제외했습니다. 구·신 경로 차이를 줄이기 위해 실행 폴더 경로만 동일 placeholder로 정규화했습니다. 기사 제목·URL·본문은 자르지 않았습니다.

## 실패를 포함한 종료코드

- `python3 _workspace/workflow-renewal-benchmark/benchmark.py`: 최종 exit 0. 양쪽 실행·측정과 원본 해시 불변 확인 성공입니다. 구버전 기능 20개가 모두 통과했다는 뜻이 아닙니다.
- `python3 _workspace/workflow-renewal-benchmark/score_gate.py before`: **exit 1**, 7개 통과/13개 실패입니다.
- `python3 _workspace/workflow-renewal-benchmark/score_gate.py after`: **exit 0**, 20개 통과입니다.
- `python3 _workspace/workflow-renewal-benchmark/supplement.py`: exit 0, 양쪽 merge CLI exit 0 및 lossless=true입니다.
- 저장 운영 입력 planner: **이전·이후 모두 exit 2**입니다. 기존 입력 `failures` 5건이 그대로 전달된 결과입니다. 후보 보존 점수는 통과하지만 이 운영 입력의 전체 수집 성공으로 보고하지 않습니다.
- 초기 benchmark: exit 1. 정적 fixture 교정 전 기존 렌더 런타임 부재 오류입니다. 로그를 지우지 않았습니다.
- usage 잘못된 값, 중복 finish, 오래된 검사·실패 검사는 의도적으로 nonzero를 발생시킨 음성 검사이며 명령별 실제 exit가 raw JSON에 있습니다.

## 생산 연결과 미측정 한계

1. 신규 slim verifier 입력은 생성 및 검증 계약이 있습니다. 모든 외부 verifier가 실제 이 파일을 소비하도록 강제하는 생산 경로까지 검증하지 않았습니다. 기존 감사 정본을 계속 보내면 위 verifier 크기 감소는 실현되지 않습니다.
2. provider usage JSON을 `finish --usage-json`에 넘길 때만 사용량이 기록됩니다. 공급자 응답을 자동 수집하는 모든 운영 호출 경로 연결은 확인하지 않았습니다. API 미실행으로 실제 토큰·비용·cache 사용량은 unknown입니다.
3. editorial receipt는 opt-in 최신성 검사입니다. 사용자 승인·판단의 충분성·검사 명령의 의미적 강도를 보증하지 않습니다.
4. Grok compact는 opt-in입니다. 기본 실행은 프롬프트 크기 절감 0%입니다.
5. HTMLParser는 CSS visibility, 본문 의미 영역, 동적 DOM을 판정하지 않습니다. 기존 v2 cache hit에는 과거 rawSnapshot/추출 결과가 없을 수 있습니다. 이번 cold-cache fixture 결과를 전체 과거 캐시에 적용하면 안 됩니다.
6. merge excerpt의 1,200자 제한 및 추출 evidence의 12,000자 제한은 여전히 있습니다. 짧은 본문 사실 fixture 통과는 임의 길이의 모든 사실 보존 증명이 아닙니다.
7. registry 중첩, 의미 중복, malformed HTML, 복잡한 운영 실패 복구에 대한 독립 적대적 검사 범위는 제한적입니다. 신버전 100점은 이 20개 검사의 만점일 뿐입니다.
8. walltime·LLM 시간은 측정하지 않았습니다. 외부 API·네트워크·패키지 설치·배포·공개 데이터 수정은 수행하지 않았습니다. 사이트 렌더·썸네일·모바일·운영 주소 검사는 미실행이므로 사이트/배포 완료를 주장하지 않습니다.

## 재현 파일

모든 benchmark 산출물 루트는 `_workspace/workflow-renewal-benchmark/`입니다.

- `RUBRIC.json`: 실행 전 고정 기준입니다.
- `benchmark.py`, `grok-probe.mjs`, `supplement.py`, `score_gate.py`: 실행 가능한 독립 검사 코드입니다.
- `fixtures/`: 합성 입력입니다.
- `hashes-before-execution.json`: 구/신 실행 코드·실운영 입력·fixture·기준·검사 스크립트 SHA-256입니다.
- `results.json`, `before/result.json`, `after/result.json`: 항목별 판정·실측 절대값·명령·실제 종료코드입니다.
- `score-gate-exits.json`: 구/신 점수 게이트의 실제 nonzero/zero 기록입니다.
- `supplement-results.json`: 비채점 병합 CLI 비교입니다.
- `attempt1-error.log`: 초기 실패 증거입니다.

오늘의 용어: 회귀검증 — 변경 전후에 같은 입력과 기준을 적용하여 기존 동작의 보존 및 목표 동작 충족을 확인하는 검사입니다.
